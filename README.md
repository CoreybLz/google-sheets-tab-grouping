# Sheets Tab Groups

A Chrome extension that adds named, color-coded tab groups to Google Sheets — surfaced in a Chrome Side Panel, synced via the spreadsheet itself.

---

## Overview

Google Sheets has no built-in tab grouping. This extension overlays a sidebar that lets you create named groups, assign sheets to them, drag-and-drop to reorganize, and apply native Google Sheets tab colors to each group. Group state is persisted inside the spreadsheet itself (a hidden config sheet), so groups travel with the file and work across devices.

## Extension Components

### `manifest.json` (Manifest V3)

- **Side Panel** — `side_panel.default_path: "sidepanel.html"`. Chrome loads this from the project root. `chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true })` is called in `background.js` so the panel opens when the user clicks the toolbar icon.
- **Content Script** — injected at `document_idle` on `https://docs.google.com/spreadsheets/d/*/edit*`. Reads the live tab DOM and handles navigation.
- **Service Worker** (`background.js`) — handles OAuth token acquisition and all Google Sheets API calls. The side panel cannot make credentialed cross-origin requests directly, so it messages the service worker.
- **Permissions** — `identity` (OAuth), `sidePanel`, `tabs`, `storage`. Host permissions cover `docs.google.com` (for the content script) and `sheets.googleapis.com` (for API calls in the service worker).
- **OAuth2** — uses `chrome.identity.getAuthToken` with the extension's embedded client ID. Tries non-interactive first; falls back to interactive if no cached token.

### `background.js` — Service Worker

All Google Sheets API v4 calls are proxied through here. The side panel sends `{ type: 'SHEETS_REQUEST', url, method, body }` messages; the service worker attaches the OAuth bearer token and returns `{ data, status, ok }`.

Key helpers:

- `getAuthToken(interactive)` — wraps `chrome.identity.getAuthToken`.
- `sheetsRequest(url, method, body)` — fetches with bearer token, handles JSON vs non-JSON responses, retries interactively on 401.

### `content.js` — DOM Bridge

Injected into the live Sheets page. Builds a `Map<sheetId, tabElement>` by parsing the tab strip DOM and listening for mutations.

Handles two message types from the side panel:

- `APPLY_GROUPS` — reads the current tab color for every sheet and returns it; also applies CSS classes for group color indicators.
- `NAVIGATE_TO_SHEET` — dispatches `mousedown` + `mouseup` + `click` on the `.docs-sheet-tab-name` span of the target tab, which is the only reliable way to switch sheets without a page navigation.

### Side Panel — React App

Built with React 18, Tailwind CSS 3, and @dnd-kit. Served via `sidepanel.html` at the project root.

#### `src/App.jsx`

Owns all application state and data-fetching:

| State | Purpose |
|-------|---------|
| `groups` | Array of `{ id, name, color, sheetIds, collapsed }` |
| `sheets` | Array of `{ sheetId, title }` from Sheets API |
| `spreadsheetId` | Parsed from the active tab URL |
| `view` | `'loading' \| 'error' \| 'main'` |
| `showNewGroup` | Controls NewGroupForm visibility |
| `toast` | `{ msg, key }` for transient notifications |

Key behaviors:

- **`loadData()`** — fetches sheet list and saved groups from the Sheets API on mount and on manual refresh.
- **`persistGroups(groups)`** — debounced write to the config sheet via `saveGroups()`.
- **`pollNativeColors()`** — runs every 9 seconds. Reads the current `tabColorStyle.rgbColor` for each sheet from the Sheets API. When a color changes, calls `nearestColor()` to find the closest palette match. If a group with that color exists, the sheet is moved into it automatically; if the sheet was in a different group, it's removed from there. Handles the "user removed a native color" case (move to ungrouped).
- **1-group-per-color enforcement** — `createGroup` merges sheets into an existing group of the same color rather than creating a duplicate. `changeGroupColor` shows a toast and refuses if the target color is already taken.

#### `src/lib/api.js`

All API interaction lives here as named ES module exports. Nothing in this file is Chrome-extension-specific except the `chrome.runtime.sendMessage` calls.

- `getToken(interactive)` — message to background.
- `apiCall(url, method, body)` — message to background; rejects on `!ok`.
- `loadSheets(spreadsheetId)` — `GET /v4/spreadsheets/{id}?fields=sheets.properties`.
- `loadGroups(spreadsheetId)` — reads the `_stg_config` hidden sheet; returns `[]` if absent.
- `saveGroups(spreadsheetId, groups)` — writes JSON to cell A1 of `_stg_config`.
- `ensureConfigSheet(spreadsheetId)` — creates `_stg_config` if it doesn't exist, then hides it.
- `setNativeTabColors(spreadsheetId, groups)` — `batchUpdate` with `UpdateSheetPropertiesRequest` for each sheet in a group, setting `tabColorStyle.rgbColor` from `hexToSheetsRgb()`.
- `clearNativeTabColors(spreadsheetId, sheetIds)` — clears tab color for sheets being removed from all groups.

#### `src/lib/colors.js`

- **`COLORS`** — 11-entry array matching Google Sheets' native color palette (Tomato, Flamingo, Tangerine, Banana, Sage, Basil, Peacock, Blueberry, Lavender, Grape, Graphite).
- **`nextAvailableColor(usedHexes)`** — returns the first palette color not already in use.
- **`nearestColor(sheetsRgb)`** — Euclidean distance in RGB space to find the closest palette entry. Returns `null` if the best match exceeds a threshold of `55000` (squared distance, ≈ 235 units) to avoid false-matching near-white or grey default tabs.

#### `src/components/GroupList.jsx`

Wraps the entire group + tab list in a single `DndContext`. Uses two different @dnd-kit primitives:

- **Groups** use `useSortable` (from `@dnd-kit/sortable`). Drag is activated only via the `GripVertical` handle (`setActivatorNodeRef`). Group order is updated with `arrayMove` in `onDragEnd`.
- **Tabs** use `useDraggable` (from `@dnd-kit/core`). Each group header also registers as a `useDroppable` target (id: `drop-group-{id}`).

`onDragEnd` dispatches by `active.data.current.type`:
- `'group'` → reorder via `arrayMove`.
- `'tab'` → if dropped on `'ungrouped-drop'`, call `onRemoveFromGroup`; if dropped on `'drop-group-*'`, call `onAddToGroup`.

A `DragOverlay` renders a floating preview of the dragged item during the drag.

`ColorPickerPopup` shows the 11-color swatch grid inline, graying out colors already used by other groups.

#### `src/components/UngroupedSection.jsx`

Registers the entire section as a `useDroppable` with id `'ungrouped-drop'`. Highlights with a blue ring when a tab hovers over it. Each ungrouped tab row has an "Add to group" dropdown and a "New group" option.

#### `src/components/NewGroupForm.jsx`

Color swatch picker + name text input. Grays out colors that are already in use. Calls `onCreate(name, color)` on submit.

## Build System

The extension always loads from the project root (`sidepanel.html` at root, `background.js` at root, etc.). React source lives in `src/` and cannot be served directly as a module script because Chrome extensions cannot load `.jsx` files.

`vite.config.js` solves this with two post-build plugins:

1. **`writeRootSidepanel`** — after each build, writes a fresh `sidepanel.html` at the project root. This file loads `./dist/assets/sidepanel.js` and `./dist/assets/sidepanel.css` using relative paths (no `crossorigin` attribute, which Chrome extensions don't support).

2. **`copyExtensionFiles`** — copies `manifest.json`, `background.js`, `content.js`, `content.css`, and `icons/` into `dist/` so `dist/` is a self-contained extension package that can also be loaded directly.

Asset filenames are pinned to `assets/[name].js` / `assets/[name].css` (no content hashes) so the root `sidepanel.html` never needs updating after a rebuild.

```
npm run build    # one-shot build
npm run dev      # watch mode (vite build --watch)
```

After building, go to `chrome://extensions`, click ↺ to reload the extension. No folder changes needed.

## Data Persistence

Groups are stored as JSON in cell `A1` of a hidden sheet named `_stg_config` inside the spreadsheet itself. This means:

- Groups survive browser restarts and profile switches.
- Groups are shared with anyone the spreadsheet is shared with.
- No external database or sync service is needed.

The config sheet is created on first save and immediately hidden via the Sheets API.

## Development Setup

```bash
npm install
npm run build
```

Load the extension in Chrome:
1. Go to `chrome://extensions`
2. Enable **Developer mode**
3. Click **Load unpacked** and select the project root directory
4. Open any Google Sheets spreadsheet and click the extension icon

For iterative development, run `npm run dev` in a terminal. Each save triggers a rebuild; click ↺ in `chrome://extensions` to reload.

## OAuth / Google API Setup

The extension uses the OAuth2 client ID embedded in `manifest.json`. To use this with your own Google Cloud project:

1. Create a project in [Google Cloud Console](https://console.cloud.google.com)
2. Enable the **Google Sheets API**
3. Create an **OAuth 2.0 Client ID** (Chrome App type)
4. Replace the `client_id` in `manifest.json` and the `oauth2.client_id` field
5. Add the extension's generated ID to the authorized origins in your OAuth client config
